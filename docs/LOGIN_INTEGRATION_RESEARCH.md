# OIDC Login Integration Research

## Исследование и внедрение автоматизации входа/выхода

**Дата:** 2025-12-20  
**Статус:** Завершено

## Резюме

Это документ описывает исследование возможностей автоматизации входа/выхода через OIDC в Mattermost с использованием plugin API. Исследование показало технические ограничения и доступные альтернативы.

## 1. Перехват вызовов /login и /logout

### Возможности Plugin API

**Результат исследования:** ❌ **Невозможно напрямую через plugin API**

#### Технические ограничения

Mattermost plugin API **не предоставляет** возможности для:
- Перехвата маршрутов `/login` и `/logout`
- Замены встроенной страницы логина
- Автоматического редиректа пользователей при доступе к `/login`

Только встроенные Enterprise-функции (SAML/OIDC) могут перехватывать эти маршруты на уровне ядра системы.

#### Технические детали

**Почему это невозможно:**
1. Плагины работают в изолированном пространстве маршрутов под `/plugins/{plugin-id}/`
2. Ядро Mattermost обрабатывает `/login` и `/logout` до того, как плагины получают контроль
3. Plugin API не предоставляет хуки для перехвата этих системных маршрутов
4. Это сделано намеренно для безопасности и стабильности системы

### Альтернативные подходы

#### A. Ingress/Reverse Proxy Rewrite (рекомендуется)

**Описание:** Настройка обратного прокси (nginx, Traefik, Istio) для редиректа `/login` на `/plugins/com.mm.oidc/login`

**Преимущества:**
- Прозрачно для конечных пользователей
- Не требует изменений кода Mattermost
- Работает для всех клиентов (web, mobile apps)

**Недостатки:**
- Требует доступа к инфраструктуре
- Необходима тщательная настройка для избежания redirect loops
- Нужно исключить API endpoints (`/api/v4/users/login`)

**Пример конфигурации (nginx):**
```nginx
location = /login {
    # Только для браузеров (User-Agent), не для API вызовов
    if ($http_user_agent ~* "Mozilla|Chrome|Safari|Edge") {
        return 302 /plugins/com.mm.oidc/login;
    }
    # API вызовы идут в обычном порядке
    proxy_pass http://mattermost:8065;
}

location /plugins/com.mm.oidc/callback {
    # Callback не должен редиректиться
    proxy_pass http://mattermost:8065;
}
```

#### B. Кнопка на странице логина (реализовано)

**Описание:** Добавление кнопки "Login with OIDC" на странице логина через `registerRootComponent`

**Преимущества:**
- Не требует инфраструктурных изменений
- Работает из коробки
- Пользователи видят явный способ входа через OIDC

**Недостатки:**
- Требует ручного клика пользователя
- Не полностью автоматический вход

**Статус:** ✅ Реализовано (см. ниже)

#### C. Custom Theme + CSS Hiding

**Описание:** Скрытие стандартной формы логина через кастомную тему и отображение только OIDC кнопки

**Преимущества:**
- Минимальное визуальное отвлечение
- Можно комбинировать с решением B

**Недостатки:**
- Не убирает функциональность стандартного логина
- CSS может сломаться при обновлении Mattermost
- Не истинный перехват

## 2. Интеграция кнопки на странице логина

### Возможности Plugin API

**Результат исследования:** ✅ **Возможно через `registerRootComponent`**

#### Технические детали

Mattermost Plugin API предоставляет метод `registerRootComponent`, который позволяет:
- Зарегистрировать React компонент на корневом уровне приложения
- Компонент монтируется глобально, включая страницу логина
- Можно условно отображать контент только на странице логина

**Пример реализации:**
```typescript
class OIDCPlugin {
  initialize(registry: PluginRegistry) {
    registry.registerRootComponent(OIDCLoginButton);
  }
}
```

#### Определение страницы логина

Компонент может определить, что находится на странице логина:
- Проверка текущего URL (`window.location.pathname === '/login'`)
- Проверка наличия DOM элементов страницы логина
- Использование Redux state (если доступен)

### Реализация

**Статус:** ✅ Реализовано в `webapp/src/components/LoginButton/`

**Функциональность:**
1. React компонент регистрируется через `registerRootComponent`
2. Компонент проверяет текущий URL
3. Если пользователь на `/login`, отображается кнопка "Sign in with OIDC"
4. Клик по кнопке редиректит на `/plugins/com.mm.oidc/login`
5. Стиль кнопки соответствует Mattermost UI

## 3. Конфигурационные опции

### Добавлена опция: Enable Auto-Redirect

**Название:** `enable_auto_redirect`  
**Тип:** boolean  
**По умолчанию:** `false`  
**Расположение:** System Console → Plugins → Mattermost OIDC

**Описание:**
Эта опция является **документационной** и указывает администраторам, что автоматический редирект возможен только через настройку инфраструктуры (reverse proxy/ingress).

**Назначение:**
- Информировать администраторов о возможности автоматического редиректа
- Предоставлять ссылку на документацию по настройке
- Планируется: в будущем может использоваться для генерации конфигурации reverse proxy

**Текущая реализация:**
- Значение опции не влияет на поведение плагина
- Используется только для информационных целей
- В будущих версиях может быть расширена для автоматической генерации конфигов

## 4. E2E тесты

### Реализованные тесты

**Статус:** ✅ Реализовано в `e2e/tests/login-integration.spec.ts`

#### Тест 1: Login Button Visibility
- Проверяет, что кнопка OIDC отображается на странице логина
- Проверяет стиль и позиционирование кнопки
- Проверяет, что кнопка НЕ отображается на других страницах

#### Тест 2: Login Button Click Flow
- Кликает по кнопке OIDC на странице логина
- Проверяет редирект на `/plugins/com.mm.oidc/login`
- Проверяет успешный вход через Keycloak
- Проверяет создание Mattermost сессии

#### Тест 3: Direct Login Flow (без кнопки)
- Прямой переход на `/plugins/com.mm.oidc/login`
- Проверяет полный OIDC flow
- Базовый сценарий без UI элементов

## 5. Выводы и рекомендации

### Итоговые результаты

| Функция | Возможность | Статус | Рекомендация |
|---------|-------------|--------|--------------|
| Перехват /login | ❌ Невозможно через plugin API | Документировано | Использовать ingress rewrite |
| Перехват /logout | ❌ Невозможно через plugin API | Документировано | Использовать ingress rewrite |
| Кнопка на странице логина | ✅ Возможно | Реализовано | Использовать как основной метод |
| Auto-redirect настройка | ⚠️ Документационная | Добавлено | Для будущего развития |
| E2E тесты | ✅ Возможно | Реализовано | Покрыты основные сценарии |

### Рекомендации по использованию

#### Для большинства инсталляций (рекомендуется)
1. Использовать кнопку "Sign in with OIDC" на странице логина
2. Пользователи кликают кнопку для входа через OIDC
3. Администраторы могут скрыть стандартную форму через custom theme

#### Для продвинутых инсталляций
1. Настроить ingress/reverse proxy для автоматического редиректа
2. Использовать предоставленные примеры конфигурации
3. Тестировать с реальным трафиком для избежания loops

#### Для enterprise окружений
1. Рассмотреть официальные Enterprise SAML/OIDC функции Mattermost
2. Они предоставляют полную интеграцию на уровне ядра
3. Данный плагин может использоваться как дополнение или альтернатива
